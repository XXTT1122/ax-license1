# 域名 / 服务器 从零到跑通

先把概念分清，很多人卡在这：

| 东西 | 作用 | 能不能省 |
|---|---|---|
| **域名** | 一个人类可读的地址（`lic.xxx.com`） | **能**：直接用 IP 也能跑（要放开 ATS） |
| **服务器** | 真正跑 `server.py` 的机器（有公网地址） | 不能省，但可以先用你自己的电脑 |
| **TLS 证书** | HTTPS 加密，iOS 默认强制 | 有域名时可免费自动签发；无域名可临时关 ATS |

所以顺序是：**先跑通（路径 0，今天就能测）→ 再上正式域名（路径 1 或 2）**。

## 路径 1：买域名 + 有公网服务器（正式方案，推荐）

### 1.1 买域名

| 渠道 | 价格参考 | 优点 | 注意 |
|---|---|---|---|
| 阿里云 / 腾讯云 | `.top`/`.xyz` 首年 ¥1–9，`.com` ¥60–80/年 | 支付宝/微信付款，中文控制台 | 国内注册商**必须实名认证**（身份证），不认证会被停解析 |
| Cloudflare Registrar | `.com` 约 $10/年（成本价，无溢价） | 免费 CDN + 免费 TLS + 免费隧道 | 需要国际信用卡/PayPal；域名转入后才能用 |
| Namecheap / Porkbun | `.xyz` 首年 $1–2 | 便宜、无实名 | 需外币卡 |

操作（阿里云为例）：
1. 阿里云 → 域名注册 → 搜一个短域名（如 `axlic.com`）→ 加入清单 → 结算（¥）
2. 控制台 → 实名认证（上传身份证，通常 1 小时内过）
3. 域名列表 → 解析设置

### 1.2 一台有公网 IP 的服务器

| 方案 | 价格参考 | 说明 |
|---|---|---|
| 阿里云/腾讯云轻量 2核2G | 活动价 ¥99–150/年 | 最省事，控制台开防火墙即可 |

### 1.3 解析 + 证书（10 分钟）

DNS 加一条 A 记录：

```
类型 A    主机记录 lic    记录值 <服务器公网IP>    TTL 600
```
→ 得到 `lic.你的域名.com`

服务器上（Ubuntu/Debian）：

```bash
# 1) 放行端口
sudo ufw allow 80,443/tcp

# 2) 装依赖
sudo apt update && sudo apt install -y python3 python3-pip certbot nginx
pip3 install cryptography

# 3) 申请证书（DNS 已生效后）
sudo certbot certonly --standalone -d lic.你的域名.com
# 证书：/etc/letsencrypt/live/lic.你的域名.com/{fullchain,privkey}.pem

# 4) 上传 axlicense/ 到 /opt/axlicense，启动
cd /opt/axlicense
python3 server/server.py --host 0.0.0.0 --port 443 \
  --tls-cert /etc/letsencrypt/live/lic.你的域名.com/fullchain.pem \
  --tls-key  /etc/letsencrypt/live/lic.你的域名.com/privkey.pem
```

自检：`curl https://lic.你的域名.com/health`

### 1.4 开机自启（systemd）

```ini
# /etc/systemd/system/axp-license.service
[Unit]
Description=AXP License Server
After=network.target

[Service]
WorkingDirectory=/opt/axlicense
ExecStart=/usr/bin/python3 server/server.py --host 0.0.0.0 --port 443 \
  --tls-cert /etc/letsencrypt/live/lic.你的域名.com/fullchain.pem \
  --tls-key /etc/letsencrypt/live/lic.你的域名.com/privkey.pem
Restart=always
RestartSec=3

[Install]
WantedBy=multi-user.target
```

```bash
sudo systemctl daemon-reload && sudo systemctl enable --now axp-license
sudo systemctl status axp-license
```

### 1.5 出包（去掉 `--ats-allow-http`）

```bash
python patch/configure.py --server https://lic.你的域名.com \
    --pubkey-from server/keys/public_b64.txt
# 然后 CI，或 inject.py 不带 --ats-allow-http
```

> 证书 90 天自动续：`certbot` 已自带 timer，`systemctl list-timers | grep certbot` 确认。

## 路径 2：有域名、没公网 IP（家里电脑对外提供 HTTPS）

用 Cloudflare Tunnel，家里电脑/树莓派都能当服务器，**不用开端口、不用公网 IP**。

```bash
# 1) 域名托管到 Cloudflare（改 NS 到 Cloudflare 给的两个地址）
# 2) 服务器上装 cloudflared
curl -L https://github.com/cloudflare/cloudflared/releases/latest/download/cloudflared-linux-amd64 -o cloudflared
chmod +x cloudflared && sudo mv cloudflared /usr/local/bin/

# 3) 登录并建隧道
cloudflared tunnel login                    # 浏览器授权，选你的域名
cloudflared tunnel create axp
cloudflared tunnel route dns axp lic.你的域名.com

# 4) 配置文件 ~/.cloudflared/config.yml
```

```yaml
tunnel: axp
credentials-file: /root/.cloudflared/<tunnel-id>.json
ingress:
  - hostname: lic.你的域名.com
    service: http://127.0.0.1:8443
  - service: http_status:404
```

```bash
# 5) 装成服务并启动
sudo cloudflared service install
sudo systemctl enable --now cloudflared
```

TLS 由 Cloudflare 终结，你本地 `server.py` 用普通 `--port 8443` 即可，出包用 `https://lic.你的域名.com`（**不要**加 `--ats-allow-http`）。

## 常见踩坑

| 现象 | 原因 | 解决 |
|---|---|---|
| 手机上一直转圈/提示网络异常 | 手机与服务器不同网段，或防火墙没放行 | 先用手机浏览器开 `/health` 验证连通性 |
| 提示「服务器响应验签失败」 | 包里公钥 ≠ 服务器私钥 | 重新 `configure.py --pubkey-from` 后**重新编译 dylib** |
| 一直卡激活页、服务器看不到请求 | 没放开 ATS 却用了 `http://` | 用 HTTPS，或出包加 `--ats-allow-http` |
| 国内服务器 443 打不开 | 未备案域名 + 80/443 被拦 | 换非 80/443 端口（如 8443）并用 Cloudflare 代理；或换境外服务器 |
| 域名解析不生效 | 未实名 / NS 未生效 | 查 `nslookup lic.你的域名.com`，等 TTL |
| 电脑重启后连不上 | 内网 IP 变了 | 路由器里给电脑绑静态 IP（DHCP 保留） |
